# UI Review — Bad People Book (2026-02-16)

## Scope
Reviewed key reader-facing routes for clarity, hierarchy, and actionability:

- `/`
- `/read`
- `/read/overview`
- `/read/chapters`
- `/read/mechanisms`
- `/read/toolkit`

## What works well

1. **Clear route-based information architecture**
   - The home page and reading hub both make route choices explicit (start / solve / reference), which reduces decision overhead for first-time readers.
2. **Visual consistency**
   - Card styles, spacing, and typography are consistent across list pages, keeping the learning surface predictable.
3. **Tone and utility alignment**
   - Mechanism and toolkit labels are concrete and action-oriented, matching the product's “small, reversible actions” promise.

## Constructive critique and recommendations

### 1) Tighten above-the-fold signal on landing and route pages
- **Observation:** Hero sections are strong, but secondary text can feel similarly weighted to primary actions.
- **Impact:** New readers may scan but not click the intended first path quickly.
- **Recommendation:** Increase visual contrast between the primary CTA and supporting text (e.g., higher button prominence, lower text contrast on helper copy).

### 2) Improve scannability on dense index pages
- **Observation:** The mechanisms list is useful but appears as a long, similar-weight stream.
- **Impact:** Important entries can be harder to prioritize quickly.
- **Recommendation:** Add optional grouping affordances (e.g., sticky tag pills, section dividers by urgency), while preserving current simple list behavior.

### 3) Strengthen status affordances for metadata badges
- **Observation:** Translation/update metadata appears in small text and low-contrast chips.
- **Impact:** Readers may overlook freshness and completeness signals.
- **Recommendation:** Raise contrast and typographic weight for high-value metadata (e.g., “updated in vX”, translation %), especially in route cards.

### 4) Reduce empty vertical tail on long desktop viewports
- **Observation:** Some pages end with significant blank space after list content on tall desktop captures.
- **Impact:** Can read as unfinished or imbalanced.
- **Recommendation:** Consider compact footer-adjacent utility blocks or adaptive max-height/list pagination only for large viewports.

### 5) Clarify global vs local navigation emphasis
- **Observation:** Top-nav “Start reading” remains visually strong even on deep reading routes.
- **Impact:** Competes with in-page next actions.
- **Recommendation:** Use route-aware nav emphasis (e.g., demote “Start reading” on `/read/*`, highlight current section).

## Suggested next pass

1. Prototype improved hierarchy for CTA + helper text on `/` and `/read`.
2. Prototype grouped scanning on `/read/mechanisms` behind a non-breaking toggle.
3. A/B test metadata chip contrast and copy density on route cards.
