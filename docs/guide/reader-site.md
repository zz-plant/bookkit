# What readers get

What the built site offers a reader. Which of it a static build serves is under [Static and server builds](./publishing.md#static-and-server-builds).

- **Wayfinding.** Each chapter says "Chapter N of M". The menu lists the reading sections and marks the current one. The home page and reading hub offer "Continue: <chapter>" for the last chapter opened on this device, with Clear, and a draft book says it is a draft on both. `[` and `]` jump to the previous and next section heading on a page.
- **Links both ways.** A mechanism page lists the chapters that use it and the glossary terms that name it. A chapter shows its prerequisites as "Read first" and the actions for its mechanisms. An action links its mechanism's examples and chapters, and a glossary term links each mechanism it lists.
- **A runbook's front door.** In a book whose frame is `runbook`, the home page and the toolkit index list every action under the situation that calls for it (the action's `trigger`), with its time and mechanism, in the order of `mechanisms` in `book.config.ts`. An action with no `trigger` shows its name alone. Under the list, a link opens "Match what’s happening" for a situation none of them names. A runbook with no action yet, and every other frame, opens with "Where to start".
- **Toolkit pages** show a runbook action's owner, review cadence, steps by situation, escalation, and drills, in the order the PDF and EPUB use. Each step is a checkbox whose whole row is the tap target; ticks are kept on the device, counted under the list, and cleared with Reset, and "Copy checklist" copies the steps as Markdown.
- **Search** matches the words a page shows, including an action's trigger and steps, a mechanism's definition, and inline code; code blocks and MDX comments are left out. Results come in one list, best match first, each naming its section and, for a heading, its page. The search field is an ARIA combobox, so a screen reader announces the result the arrow keys select. A query no page fully matches shows pages with any of its words and says so; with no match at all, the panel keeps its "Go to" links. In a runbook book an action goes ahead of a chapter or mechanism that matches about as well. A 404 page offers a search for the words of the missing address.
- **Releases.** The release notes page and RSS feed list each release note, with dates as written, whatever the build's time zone. The version archive links each older version to its entry in the release notes.
- **Ask** (server runtime only): a panel that answers a question from the book's passages and cites them. It is on unless `features.aiQa` is `false` (the starter sets `false`). The server writes the answer with `OPENAI_API_KEY` or `GROQ_API_KEY`; without either, the panel shows the matching passages. A line above each answer says who wrote it: the book's own words stay in the book's typeface, and a model's are set in the monospace the site uses for everything it adds around the book. To rank passages, the panel can run two models in the reader's browser, `Xenova/all-MiniLM-L6-v2` and `Xenova/ms-marco-MiniLM-L-6-v2`: about 48 MB from Hugging Face (`huggingface.co`) and a 10 MB runtime (ONNX Runtime's WebAssembly) that the book's own site serves, kept in the browser once downloaded. On the reader's first question the panel says this and asks, Download or Not now, before it fetches anything; the question runs once they choose, and the browser remembers the choice. With Not now, passages are matched by their words, the server still writes the answer when it has a key, and a button under the form asks again. The panel's "Turn off" button disables Ask in that browser.
- **What search engines and link previews see.** A page's title is its own name and the book's short title; its description is the chapter's `summary`, a definition, an action's trigger, or the first paragraph. Every page gets a PNG link-preview image in the book's typefaces, and ends with a colophon: title, byline, `site.defaultMeta.description`, and a link to start reading.
